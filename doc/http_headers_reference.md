## Table columns meaning

* __Req:__ "Y" = the header can be used in requests; "-" the header is not supposed to be used in requests
* __Resp:__ "Y" = the header can be used in responses; "-" the header is not supposed to be used in responses
* __Singleton:__ the header is supposed to appear at most once in a message
* __List:__ the header value is or can be a list of elements (note that different headers can use different parsing rules and separator characters).
    An asterisk is used to denote headers for which a known rule exists specifying how to handle the presence of multiple headers.
* __Structured__ Type: whether the header value follows the "Structured Field Types" syntax, as defined in [RFC 9651](https://httpwg.org/specs/rfc9651.html)
* __DQ encoding:__ if the header value allows for spans of text delimited by double-quotes, which encoding rule is applied to the text spans delimited by the double-quotes

  * none = no escaping (the logical conclusion being that DQ characters are not allowed within the text spans enclosed by the double-quotes)
  * qs = quoted-string, as per [RFC 9110]https://httpwg.org/specs/rfc9110.html#rfc.section.5.6.4
  * sf = structured field, as per [RFC 9651](https://httpwg.org/specs/rfc9651.html)
* __Regexp:__ when a header value can be validated with a regexp to be _fully_ compliant with the relevant spec, it should be written here, unless too big or unwieldy. Uses `preg` regexp syntax.
* __Allowed chars:__ a looser validation of the header value than the Regexp: merely lists which characters (aka. octets in the HTTP world) are allowed
* __HTTPS only:__ "This feature is available only in [secure contexts (HTTPS)](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Secure_Contexts), in _some or all_ supporting browsers"
* __Status IANA:__ the status in the IANA registry. "-" for headers which are not registered, but are eg. listed on MDN

Header lines can not contain CR, LF, DEL, NUL chars.

`token` rule: A-Z / a-z / 0-9 / "!" / "#" / "$" / "%" / "&" / "'" / "*" / "+" / "-" / "." / "^" / "_" / "`" / "|" / "~"

Chars excluded from token: x00-x1F / " " / '"' / "(" / ")" / "," / "/" / ":" / ";" / "<" / "=" / ">" / "?" / "@" / "\[" / "\" / "]" / "{" / "}" / x7F / x80-xFF

`qs` rule: '"' followed by x09 / " " / "!" / "#"-"~" / x80-xFF /  "\x09" "\ -~" / "\x80-xFF" followed by '"' - in other words: can contain all chars except DEL and CTRL ones (x00-x1F)

`parameter` rule: token / "=" / qs

The 'token' rule used by Structured Types allows chars of token plus ":" and "/"

The 'string' rule used by Structured Types only allows escaping of '"' and "\"
